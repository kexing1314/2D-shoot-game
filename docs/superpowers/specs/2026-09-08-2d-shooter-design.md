# 2D 联机射击小游戏 · 设计文档

日期：2026-09-08
状态：已与需求方逐节确认

## 1. 需求汇总

- 网页运行的 2D 平面射击小游戏，联机可玩
- 房间码进房，每房 2–4 人
- PvP + 打怪混合：同场有其他玩家和怪物，可互相攻击
- 操作：WASD 移动，方向键四向射击
- 血条 + 无限重生 + 击杀计分，无胜负结算，休闲局
- 地图较大、视野有限（镜头跟随）、右上角小地图（雷达：显示全部玩家和怪物）
- 固定墙体障碍（挡移动、挡子弹）
- 小 Boss 定时刷新，击杀后掉落强化武器
- 几何图形画风，零美术素材
- 先跑本机/局域网，后续部署云服务器（不同 WiFi 的人可玩）
- 只做朋友休闲局，不做防挂加固

## 2. 技术方案（已选定：方案 A）

**纯 Node.js + ws + 原生 Canvas，权威服务器。**

- 服务器是唯一真相：全部游戏状态（位置、HP、子弹、怪物、Boss、拾取物、分数）只在服务器上计算
- 客户端只做两件事：把按键状态发给服务器；把服务器广播的状态画到 Canvas
- 一个 Node 进程同时提供：`node:http` 静态托管（大厅页 + canvas 页）+ 同端口升级 WebSocket。不用 express，不用打包工具
- 唯一 npm 依赖：`ws`

已否决的备选：
- Phaser 引擎：几何图形用不上引擎，联机部分照样要自己写
- WebRTC P2P：仍需信令服务器，NAT 不稳定，主机掉线全灭

## 3. 文件结构

```
game/
├── package.json     # 唯一依赖：ws
├── server.js        # HTTP托管 + WebSocket + 房间管理 + 游戏模拟循环
├── shared.js        # 双端共享：地图墙布局、全部数值常量、武器表
├── test.js          # 纯逻辑 assert 测试（node test.js 直接跑）
└── public/
    ├── index.html   # 大厅界面 + 游戏 canvas
    └── client.js    # 按键采集、镜头、渲染、HUD
```

`shared.js` 浏览器端用 `<script src>` 直接引入，地图和数值只写一份，双端永不分叉。

## 4. 服务器游戏模拟

固定帧率 **20 tick/s（50ms）**，每 tick 顺序：读按键 → 移动玩家 → 移动子弹/怪物/Boss → 碰撞结算 → 刷怪 → 全量广播 `state`。

### 4.1 地图

- 竞技场 **3200×1800**，四周边界墙 + 中间固定若干矩形墙
- 全部墙体定义在 `shared.js` 数组里
- 玩家 = 半径 16 的圆；碰撞用圆 vs 矩形，X/Y 轴分开解算（撞墙贴墙停下）

### 4.2 移动与射击

- 玩家 HP 100，移速 200 px/s；服务器存按键状态，每 tick 积分位移
- 方向键开火，射速由武器表决定（默认手枪 300ms/发，按住连发同速率）
- 子弹属性完全由武器表驱动；碰墙、碰玩家、碰怪物或出图即消失（穿透弹除外）

### 4.3 武器表（数据驱动，加武器 = 加一行）

```js
const WEAPONS = {
  pistol:  { rate: 300, dmg: 25, speed: 500, count: 1, pierce: false, size: 3 },
  mg:      { rate: 100, dmg: 15, speed: 500, count: 1, pierce: false, size: 3 },
  shotgun: { rate: 600, dmg: 15, speed: 500, count: 3, spread: 15, pierce: false, size: 3 },
  cannon:  { rate: 800, dmg: 60, speed: 300, count: 1, pierce: true,  size: 8 },
}
```

- 射击逻辑只写一次：读表生成子弹（count>1 时以射击方向为中心 ±spread 度扇形展开）
- pierce=true 的子弹穿过怪物和玩家不消失，撞墙才消失
- 掉落时从表中随机选一个非 pistol 武器

### 4.4 普通怪物

- 每 5 秒在地图边缘随机点刷一只，房间上限 **20 只**（单人也可玩 PvE）
- 行为：直线追最近的玩家（60 px/s），碰撞造成 10 伤害，之后 1 秒攻击冷却
- HP 50（默认手枪两发），死亡即消失

### 4.5 小 Boss

- 每 40 秒在远离所有玩家的随机点刷一只，场上同时最多 **2 只**
- 大紫色圆（半径 32），HP 300，移速 80，碰撞伤害 25，攻击冷却 1 秒
- 行为同普通怪（追最近玩家），不做远程攻击
- 死亡时在原地掉落一个武器拾取物

### 4.6 武器拾取物

- 旋转小方块，玩家碰到即拾取，替换当前武器
- 持有规则：**保留到死亡为止**，重生变回 pistol；玩家死亡时其武器掉落在死亡位置，可被任何人拾取（PvP 争夺点）

### 4.7 死亡、重生、计分

- HP ≤ 0 死亡，3 秒后在离其他玩家最远的刷新点重生，HP 回满
- 计分板两项：击杀（打死玩家算开枪者的，打死怪物/Boss 也算）、死亡
- 无胜负结算，随时可退，分数仅当局房间内有效

### 4.8 房间生命周期

- 创建房间 → 4 位房间码；输码加入 → 立即出生进游戏（无等待阶段）
- 玩家全退 → 房间及其模拟定时器销毁
- 断线 → 角色移除、分数清掉；重连输码即新角色进入（不做重连保分）

## 5. 网络协议（JSON over WebSocket）

客户端 → 服务器：

| 消息 | 时机 | 内容 |
|---|---|---|
| `create` | 点"创建房间" | `{t:"create", name}` |
| `join` | 点"加入房间" | `{t:"join", name, code}` |
| `input` | 按键变化时（keydown/keyup 触发才发） | `{t:"input", keys:{w,a,s,d,up,down,left,right}}` |

服务器 → 客户端：

| 消息 | 时机 | 内容 |
|---|---|---|
| `joined` | 进房成功 | 玩家 id、房间码、玩家颜色 |
| `state` | 每 tick（20Hz） | 全部玩家（位置/HP/武器/分数/死亡倒计时）、怪物、Boss、子弹、拾取物 |
| `error` | 房间码不存在 / 房间满 | 提示文本，客户端弹回大厅 |

全量广播，不做增量 diff、不压缩（2–4 人 + 20 怪 + 2 Boss，每次几 KB，diff 是负优化）。

## 6. 客户端

### 6.1 大厅页

- 昵称输入框 + "创建房间"按钮
- 房间码输入框 + "加入"按钮
- 创建成功后大字显示房间码，便于转发给朋友

### 6.2 游戏画面

- Canvas 视口 **1280×720**，镜头跟随自己的角色，地图边缘处钳制不越界
- 绘制：墙（矩形）、玩家（彩色圆 + 头顶昵称 + 血条，自己描白边）、怪物（红色三角）、Boss（大紫圆）、子弹（小黄点，尺寸按武器表 size）、拾取物（旋转小方块）
- 视野裁剪：只画镜头视口内的实体
- **不做插值平滑**：按收到的坐标直接画；若 20Hz 顿挫感明显，后续再加客户端 lerp（几行改动，不动架构）

### 6.3 HUD

- **右上角小地图**（约 200×112）：全图缩放轮廓 + 墙体 + 全部玩家/怪物/Boss/拾取物位置点（雷达模式），Boss 为大紫点
- **左上角计分板**：每个玩家的击杀/死亡
- 死亡时屏幕中央显示"3 秒后重生"

## 7. 异常处理

- 房间码不存在 / 房间满（>4）→ `error` 消息 → 客户端弹提示回大厅
- 玩家断线 → 角色移除；重连重新输码
- 玩家全退 → 房间销毁，清理定时器，无僵尸房间
- 服务器重启 → 房间全部蒸发；客户端检测 WebSocket 关闭 → 弹"与服务器断开"回大厅。**不做状态持久化**

## 8. 部署

- 阶段一（本设计范围）：本机 `node server.js`，局域网朋友用 `ws://本机IP:端口` 加入
- 阶段二（后续，不在本期实现）：云服务器部署。同一份代码，前置要求只有 WSS（https 页面只能连 wss://）。两条路任选：Render/Fly.io/Railway 托管平台（TLS 自动），或 VPS + Caddy 反代（自动签证书）
- 不做防挂加固：协议只收按键状态，服务器自算一切，客户端无上报坐标的口子

## 9. 测试策略

- **纯逻辑**（碰撞、伤害、扇形展开、武器表读取）：`test.js`，assert 断言，`node test.js` 直接跑，无测试框架
- **联机行为**：本机起服务器，开两个浏览器窗口互射验证同步；再用第二台设备连局域网 IP 验证跨机器
- **手感数值**（移速、射速、Boss 强度、刷怪间隔）：不做自动化测试，试玩后改 `shared.js` 单点调优

## 10. 刻意简化清单（含升级路径）

| 简化 | 何时升级 |
|---|---|
| 20Hz 全量广播、无增量/压缩 | 房间人数或实体量大到带宽可测量时 |
| 客户端无插值 | 试玩觉得顿挫时加 lerp |
| 怪物/Boss 只会"追最近玩家" | 想要更多怪种行为时在模拟循环加分支 |
| 断线不保分、无账号体系 | 出现长期玩家群体再考虑 |
| 服务器无状态持久化 | 基本永远不需要（休闲局） |
